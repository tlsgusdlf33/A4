# 점검 런북 — 매 회차 실행 순서

Google Drive MCP 도구 기준. `<LAST>` = 직전 점검 시각(RFC3339 UTC).

## 1. 신규 프로젝트 폴더 감지 (최우선)

```
search_files:
  mimeType = 'application/vnd.google-apps.folder'
    and parentId = '10ZY6eP8fz8qN7qQDd8d0CvAhgijnlyEN'
    and createdTime > '<LAST>'
```
결과가 있으면 → `docs/10_신규프로젝트_펌프선정_절차.md` 착수.
해당 폴더 하위 `# spec 정리` 를 `parentId = '<신규폴더ID>'` 로 조회해 기술규격서를 읽는다.

## 2. 신규 Outlook 메일 감지

```
search_files:
  mimeType = 'application/vnd.ms-outlook' and createdTime > '<LAST>'
  (excludeContentSnippets: true, pageSize: 100)
```
- 파일명 `<번호> <YYMMDD> <발신-수신> <요지>.msg` 를 파싱해 프로젝트별 번호순으로 정렬.
- 발신이 외부(발주처/벤더)이고 뒤에 `기술-<상대처>` 또는 `영업-<상대처>` 회신이 없으면 **미회신**.

## 3. 그 외 변경

```
search_files:
  createdTime > '<LAST>' and owner = 'me'
```

## 4. .msg 본문 읽기

`read_file_content` 는 `application/vnd.ms-outlook` 미지원.
방법 선택은 [`docs/20_메일본문_확인방법.md`](../docs/20_메일본문_확인방법.md) 참고.

기본 경로(원본 37 KB 이상):

```
download_file_content(fileId)                 # 결과가 크면 자동으로 파일 저장됨
python3 tools/read_msg.py <저장된파일> --attach-dir /tmp/att
```

출력: 제목 / 발신 / 수신 / 참조 / 발신일시 / 첨부목록 / 본문
(평문 → HTML → RTF 압축 순으로 자동 선택, CP949·UTF-16 자동 판별)

37 KB 미만 메일은 base64 가 대화에 그대로 실려 파일로 못 넘긴다.
이 경우 첨부파일을 대신 읽거나(같은 폴더에 별도 저장되어 있음),
노트북에서 `tools/msg_to_txt.ps1` 로 `.txt` 사이드카를 만들어 두면
이후 `read_file_content` 한 번으로 본문을 읽을 수 있다.

## 5. 산출물

- `reports/<YYYY-MM-DD>_01도서_변경점검.md`
- 미회신 건별 `drafts/<번호>_<상대처>_<요지>.md`
