# 01 도서 모니터링 / 업무 자동화

Google Drive `내 컴퓨터 > 내 노트북 > 01 도서` 폴더의 변경을 주기적으로 확인하고,
변경 유형에 따라 업무 산출물을 만들어 두는 작업 저장소.

## 감시 대상

| 항목 | 값 |
| --- | --- |
| 루트 폴더 | `01 도서` (`1K55nnevLIasQRLTSG2FPlGTTNDQs3pY4`) |
| 구조 | `01 도서 / <연도> / <수주여부_프로젝트번호_발주처_현장-품목> / ...` |
| 현재 진행 연도 | `2026` (`10ZY6eP8fz8qN7qQDd8d0CvAhgijnlyEN`) |

## 동작 규칙

1. **`.msg`(Outlook 메일)가 새로 저장되면** → 요청 건으로 간주.
   - 발신처가 외부(발주처/벤더)이고 뒤따르는 회신 메일이 없으면 **미회신 건**으로 올린다.
   - 해당 건의 회신 초안 또는 필요한 기술자료를 `drafts/` 에 작성한다.
2. **프로젝트 폴더가 새로 생기면** → **최우선 업무**.
   - `# spec 정리` 폴더의 기술규격서를 읽고 펌프 모델을 선정한다.
   - 데이터시트 / 성능곡선 / 외형도 / 조립도 4종을 작성한다.
   - 상세 절차: [`docs/10_신규프로젝트_펌프선정_절차.md`](docs/10_신규프로젝트_펌프선정_절차.md)
   - `.msg` 본문 확인: [`docs/20_메일본문_확인방법.md`](docs/20_메일본문_확인방법.md)
3. 그 외 파일 개정(Rev 상승)은 리포트에만 기록한다.

## 디렉터리

- `docs/` : 감시 규칙, 폴더 맵, 표준 업무 절차
- `reports/` : 회차별 변경 점검 결과
- `drafts/` : 회신 메일 / 제출 메일 초안
- `tools/` : 점검 실행 런북, `.msg` 본문 추출기(`read_msg.py`), `.txt` 사이드카 변환기(`msg_to_txt.ps1`)
