# `.msg` 메일 본문 확인 방법

Google Drive MCP 의 `read_file_content` 는 `application/vnd.ms-outlook` 을 지원하지 않는다.
아래 네 가지 중 상황에 맞는 것을 쓴다. **A 와 C 는 이 저장소에서 실제로 동작을 확인했다.**

| 방법 | 준비 | 본문 | 첨부 | 비고 |
| --- | --- | --- | --- | --- |
| A. Drive 다운로드 + `tools/read_msg.py` | 없음 | O | O | **검증 완료.** 지금 바로 쓸 수 있는 기본 경로 |
| B. `.txt` 사이드카 자동 생성 | 노트북 1회 설정 | O | 이름만 | **가장 권장.** 이후 Drive 가 본문을 직접 읽음 |
| C. 첨부파일 직접 열람 | 없음 | X | O | 첨부가 이미 같은 폴더에 저장되어 있는 경우 |
| D. Gmail 커넥터 | 메일 포워딩 | O | O | 회사 메일이 Gmail 로도 들어올 때만 |

---

## A. Drive 다운로드 + `tools/read_msg.py` — 검증 완료

```
1) download_file_content(fileId)        # base64 반환
2) 결과가 크면 자동으로 .txt(JSON) 로 저장됨
3) python3 tools/read_msg.py <저장된파일 또는 .msg> [--attach-dir DIR] [--full]
```

`tools/read_msg.py` 가 처리하는 것

- 제목 / 발신(이름·주소) / 수신 / 참조 / **발신일시** / 첨부 목록
- 본문 우선순위 : 평문(`PR_BODY`) → HTML(`PR_HTML`) → **RTF 압축(`PR_RTF_COMPRESSED`, LZFu 직접 해제)**
- 한글 인코딩 : UTF-16LE 및 CP949 자동 판별
- `--attach-dir` 로 첨부파일(PDF·도면 등) 디스크 추출 → 이후 `read_file_content` 로 열람

검증 결과

```
$ python3 tools/read_msg.py 713.msg
제목  : Re: [PH20] COP Suction Can 및 Base Plate 납기 관련 확인 요청 건
발신  : 강현식(HYUNSIK KANG) <janeighth83@poscoenc.com>
일시  : 2026-09-17 23:04:32 UTC
첨부  : image001.png (9,924B)
--- 본문 (plain) ---
… Suction Can과 Base Plate는 계약 납기에 맞춰 납품해 주시기 바랍니다.

$ python3 tools/read_msg.py 366.msg --attach-dir ./att
첨부  : … A3H85965 1 (BOTH) Rev P4 KSM.pdf (82,572B), A3H85962 1 (MM) Rev P6 KSM.pdf (73,158B)
→ ./att 에 KSM 수정도면 2건 추출 완료
```

**제약** : `download_file_content` 는 결과가 약 50,000자를 넘을 때만 파일로 저장된다.
base64 는 원본의 약 1.37배이므로 **원본 37 KB 이상인 `.msg` 만 이 경로가 매끄럽다.**
그보다 작은 메일은 base64 가 그대로 대화에 실려 파일로 못 넘긴다 → 방법 B 를 쓴다.

## B. `.txt` 사이드카 자동 생성 — 가장 권장

노트북에서 `tools/msg_to_txt.ps1` 을 돌리면 `.msg` 옆에 같은 이름의 `.txt` 가 생긴다.
Drive 가 `.txt` 를 그대로 읽으므로 이후에는 `read_file_content` 한 번으로 끝난다.
크기 제약도, 파싱도 필요 없다.

```powershell
powershell -ExecutionPolicy Bypass -File tools\msg_to_txt.ps1 `
  -Root "$env:USERPROFILE\Google Drive\내 컴퓨터\내 노트북\01 도서\2026"
```

- 최초 1회 전체 변환 후, 작업 스케줄러에 `-Since 3` 으로 매일 등록하면 신규분만 변환된다.
- Outlook 설치 PC 에서만 동작(Outlook COM 사용). 이미 `.txt` 가 있으면 건너뛴다.
- Outlook 없이 하려면 : `pip install extract-msg` 후
  `python -c "import extract_msg,glob,os; [open(os.path.splitext(p)[0]+'.txt','w',encoding='utf-8').write(extract_msg.Message(p).body or '') for p in glob.glob('**/*.msg',recursive=True)]"`

## C. 첨부파일 직접 열람 — 검증 완료

현재 업무 방식상 `.msg` 의 첨부는 대부분 같은 폴더에 별도 저장되어 있다.
(예: `366 260918 KSM-기술 …msg` 옆에 `366 A3H85962 1 (MM) Rev P6 KSM.pdf`)

```
search_files: parentId = '<메일이 있는 폴더 ID>'
read_file_content(<첨부 PDF/XLSX 의 fileId>)     # PDF·XLSX·이미지 모두 지원
```

본문 없이 기술 내용만 필요할 때 가장 빠르다. 파일명 앞 일련번호가 메일 번호와 같아 짝을 찾기 쉽다.

## D. Gmail 커넥터

회사 메일(`@cwhydro.co.kr`)이 Gmail 로도 수신된다면 `.msg` 를 거치지 않고 본문을 바로 읽을 수 있다.

```
search_threads(q: "from:poscoenc.com Suction Can")
get_message / get_thread
```

현재는 Outlook 전용으로 보이므로 보조 수단이다. 포워딩을 걸면 A·B 없이도 즉시 조회가 된다.
